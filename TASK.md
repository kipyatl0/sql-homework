# Задача

Провести аудит производительности базы данных: проанализировать медленные запросы через EXPLAIN ANALYZE, создать оптимальные индексы, устранить проблему N+1 в ORM и описать стратегию масштабирования.

Задание закрепляет темы модуля "СУБД": EXPLAIN ANALYZE, индексы (частичные, композитные, INCLUDE), проблема N+1, партиционирование, PgBouncer.

Что нужно сделать

## 1. Создание и наполнение тестовых таблиц

Создать таблицы orders и order_items в PostgreSQL. Наполнить тестовыми данными: минимум 100 000 заказов и 300 000 позиций. Данные должны быть реалистичными: разные статусы, даты за последний год, разброс сумм.

SQL-скрипт для создания таблиц:

```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    total_amount NUMERIC(10, 2) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT now(),
    updated_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER NOT NULL REFERENCES orders(id),
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,
    price NUMERIC(10, 2) NOT NULL
);
```



## 2. Анализ запросов через EXPLAIN ANALYZE

Выполнить четыре аналитических запроса до создания индексов. Для каждого запроса:

Привести вывод EXPLAIN ANALYZE.
Указать узкое место (Seq Scan, Nested Loop, Sort и т.д.).
Предложить индекс для оптимизации.
Запросы:

Все заказы пользователя за последний месяц со статусом completed.
Топ-10 товаров по количеству продаж за последний квартал.
Средний чек по дням за последние 30 дней.
Все заказы с суммой выше 10 000 и их позиции (JOIN).

## 3. Создание индексов

На основе анализа создать минимум три индекса:

Композитный индекс -- например, (user_id, created_at) для запроса 1.
Частичный индекс -- например, WHERE status != 'cancelled' для фильтрации активных заказов.
Индекс с INCLUDE -- например, для Index Only Scan на запросе 3.
После создания каждого индекса повторить EXPLAIN ANALYZE и показать изменение плана (Index Scan вместо Seq Scan).

## 4. Демонстрация и устранение N+1

Написать Python-код (SQLAlchemy), который:

Демонстрирует проблему N+1: загрузка заказов и обращение к order.items в цикле.
Исправляет N+1 двумя способами: joinedload и selectinload.
Показывает разницу в количестве SQL-запросов через логирование (echo=True).

## 5. Стратегия масштабирования

Описать текстом план масштабирования таблицы orders при росте до 50 млн строк:

- Партиционирование (по какому полю, тип RANGE)
- Репликация (master/replica)
- PgBouncer (режим, размер пула)
- Когда партиционирование, а когда шардинг
